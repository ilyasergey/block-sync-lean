# 2026-04-25 — Phase 4.5: Timing infrastructure + liveness statements

User feedback: "Why can't we do liveness facts and appendix C lemmas?" /
"Add the necessary bits for liveness. No probabilities so far."

Cause of the deferral was structural, not effort: our `Trace = Nat → S`
indexed by step number, not wall-clock time. So liveness lemmas (paper
§5 Lemmas 1, 2; Appendix D Lemmas 8, 9, 11, 12; Theorem 6) and Appendix C
deterministic latency bounds couldn't be precisely stated. Phase 4.5
adds the missing scaffolding.

## What's new

### `BlockSynchroniser/Timing.lean` (new module)

- `TimeMap := Nat → Nat` — wall-clock map on step indices.
- `TimeMap.Monotone`, `TimeMap.Unbounded`, `TimeMap.WellFormed`
  predicates.
- `TimeMap.stepIsTime`: trivial step-equals-time map (sanity test;
  `WellFormed` proven).
- `StepAtOrAfter`, `exists_step_after`.
- **`PartiallySynchronous system trace time`**: post-GST, time
  advances by ≤ Δ per step. The minimum constraint on the abstract
  model needed to state liveness; finer-grained per-message delivery
  semantics await a full network model.

### `BlockSynchroniser/Beluga/Theorems.lean` (refined)

`lemma1_honest_round_entry` and `lemma2_round_latency` now take
`(time : TimeMap) (h_time : time.WellFormed) (h_sync :
PartiallySynchronous system (belugaTrace system) time)` and quantify
properly: `∀ k, time k ≥ system.GST + 3 * system.Δ → ...` for L1,
`time k' ≤ time k + 3 * system.Δ ∧ ...` for L2. Replaces the abstract
`∃ k` that was a stand-in.

### `BlockSynchroniser/Mysticeti/Liveness.lean` (new module — paper Appendix D.2)

Five new theorem statements + `theorem6_consensus_liveness`:

| # | Statement | Time bound |
|---|---|---|
| **L8** | Honest leader's block referenced by every honest validator next round | `time k + 4Δ` |
| **L9** | Honest validators create a certificate for an honest leader's block | `time k + 4Δ` |
| **L11** | Every undecided leader block eventually gets decided | `∃ k' ≥ k₀` post-GST |
| **L12** | Block referenced by 2f+1 ⇒ all honest output `block_accept` | `∃ k' ≥ k₀` post-GST |
| **T6** | Mysticeti-Beluga consensus liveness | skeleton |

All carry verbatim PROVIDED SOLUTION sketches drawn from the paper.
All statements take `time : TimeMap` + `WellFormed` + `PartiallySynchronous`
hypotheses.

## Out of scope (still)

- App C **Lemmas 6, 7, Theorem 5** — probabilistic (expected-latency
  bounds). Genuinely require a probability framework.
- Detailed network model (per-validator views, explicit messages with
  delivery timestamps). Our `SystemState` exposes a *global* operation
  log; the timing model adds wall-clock annotations on top, sufficient
  to *state* liveness but a richer per-validator view is needed for
  full proofs.
